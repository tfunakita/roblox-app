🗺️3つのシステム全体像
⏱️
システム①
ラップタイム
スタート/ゴールライン通過を検知してタイムを計測・表示する
🔄
システム②
コース復帰
コースアウト後2秒で1秒前の位置に自動テレポートする
👻
システム③
ゴースト
前周の自分の走りを録画して次周に幽霊として再生する

3つはすべて連動しています。①でゴール判定 → ②でコース維持 → ③でゴール後にゴーストを召喚。
スクリプトの配置場所：ServerScriptService（コース復帰・ゴースト）とVehicleSeat配下（ラップ・カウントダウン）の2か所が中心。

⏱️ システム① ラップタイム計測 ＆ カウントダウン
1
スタート台・ゴールラインを配置 → Transparency 0.5の半透明ブロック → CanCollide OFF、Anchored ON
2
カウントダウンを実装 → 5秒前から数字表示 → 3秒前からサウンド → 0でカート走行ロック解除
3
ゴールライン通過を検知 → Touched イベントでラップカウント → 設定周回数に達したらゴール表示
4
タイムを表示・リセット → ベストラップ / 周回タイムをHUDに表示 → ゴール後10秒でリスタート
STEP 1スタート台・ゴールラインの設定

やること
スタート台とゴールラインをそれぞれ別の半透明ブロックとして配置する。カートをちょうど覆う横幅に設定する。

プロパティ値理由
Transparency0.5半透明で見えるが邪魔にならない
CanCollideOFF当たっても弾かれない（すり抜ける）
CanTouchONTouchedイベントを受け取るために必要
AnchoredON落下防止

名前を正確に付ける
スクリプトから参照するのでパーツ名を決めておく（例：「StartLine」「FinishLine」）。名前が変わるとスクリプトがエラーになる。

STEP 2カウントダウンと走行ロックの実装

カウントダウンの流れ

-- カウントダウンのタイミング（RaceManagerスクリプト内） -- 5秒前：数字の表示を開始 -- 3秒前：カウントダウン音を再生 -- 0秒 ：走行ロック解除（カートが動けるようになる） -- 走行ロック中はスロットル入力を無効化しておく if not raceStarted then seat.Throttle = 0 end

確認ポイント
カウントダウン中にアクセルを踏んでもカートが動かないことを確認する。0になった瞬間に動き始めるのが正しい動作。

STEP 3ゴールライン通過とラップタイム計測

やること
ゴールラインの Touched イベントでラップカウントを増やし、タイムを記録する。

-- ゴールライン通過時の処理（概要） FinishLine.Touched:Connect(function(hit) -- カートのパーツかどうかチェック local lapTime = tick() - lapStartTime -- タイム計算 lapCount = lapCount + 1 if lapCount >= totalLaps then -- ゴール処理（FINISH表示 → 10秒後リスタート） else -- 周回タイム更新・次のラップ開始 lapStartTime = tick() end end)

周回数の変更
変数 totalLaps の数値を変えるだけで1周・3周・5周に変更できる。

🔄 システム② コースアウト自動復帰
1
RunServiceで毎フレーム処理 → Heartbeatで継続してプレイヤーの位置を記録する
2
コース上にいるか判定 → カートの4隅がコースパーツの上にあるかをRaycastで確認
3
コースアウト2秒後に復帰 → 「コースを外れた瞬間から1秒前」の記録位置へテレポート
STEP 1スクリプトの配置場所とサービスの宣言

配置場所
ServerScriptService の中にスクリプトを置く（名前は「リプレイ」や「CourseReset」など自由でOK。スクリプトの動作には影響しない）。

-- 必ず最初に宣言するサービス local RunService = game:GetService("RunService") local Players = game:GetService("Players") -- コースのパーツを取得（名前は自分のワークスペースに合わせる） local safeZone = workspace.マリオカートコース1.コース
STEP 2位置の記録と安全な場所の判定

やること
プレイヤーが乗っているカートのHumanoidRootPartの位置を毎フレーム記録し続ける。カートの左右4方向の点がコースパーツ上にあるかで「コース上かどうか」を判定する。

-- 位置の記録（例） local posHistory = {} -- 過去の位置を格納するテーブル RunService.Heartbeat:Connect(function() local rootPart = -- HumanoidRootPartを取得 table.insert(posHistory, { pos = rootPart.CFrame, time = tick() }) -- 古いデータは削除（直近数秒分だけ保持） while posHistory[1] and tick() - posHistory[1].time > 5 do table.remove(posHistory, 1) end end)
STEP 32秒後に1秒前の位置へ復帰する処理

復帰ロジックの考え方

タイミング何が起きるか
コースアウト直後タイマーをスタート（まだ走り続けられる）
コースアウトから2秒後posHistoryから「1秒前の位置」を探して取得
テレポート実行HumanoidRootPartをその位置にCFrameで移動

「1秒前」の意味
コースを外れた瞬間ではなく、その1秒前の位置（=まだコース上にいた地点）に戻す。これにより壁際にうまく復帰できる。

確認ポイント
海や崖の外に落ちたとき、2秒後にコース上の直前の地点に戻ることを確認する。復帰後のスピードは通常通りになる。

👻 システム③ ゴーストシステム
1
ゴーストモデルを準備 → ReplicatedStorageに専用カートを配置 → Transparency 0.2・CanCollide OFF
2
走行中にデータを録画 → 毎フレーム、自分のカートのCFrameとシートの状態を記録
3
ゴール後10秒で再生 → リスタート時にゴーストモデルを出現させ、録画データ通りに動かす
STEP 1ゴーストモデルの準備（ReplicatedStorage）

やること
本物のカートとは別に「ゴースト専用カート」を作り、ReplicatedStorage の中に「ゴーストモデル」という名前で置く。

設定項目値理由
Transparency0.2透けて見える幽霊っぽい見た目
CanCollideOFF（全パーツ）本物のカートとぶつかって弾かれないように
AnchoredOFFスクリプトで動かすので物理は不要
VehicleSeat誰も乗れない設定プレイヤーが誤って乗らないように

確認方法
ゴーストモデルが見つからない場合はスクリプト内でエラーが出る。必ず「ゴーストモデル」という名前で正確に配置すること。

STEP 2走行データの録画（RaceManagerスクリプト）

配置場所
ServerScriptService の中に「RaceManager」という名前のスクリプトを作成する。

-- 録画データを格納するテーブル local ghostData = {} -- 毎フレーム、プレイヤーの位置を記録 RunService.Heartbeat:Connect(function() if isRacing then table.insert(ghostData, { cframe = humanoidRootPart.CFrame, -- シートの状態も記録（ハンドル・アクセルなど） }) end end)

ゴール判定との連携
ゴールラインを通過した時点で録画を停止し、ghostDataを保存する。次のラップ開始時に空のテーブルでリセットして新たに録画を始める。

STEP 3ゴール後10秒でゴースト召喚・再生

ゴール後の流れ

-- ゴール後の処理 -- 1. ラップタイムを表示 -- 2. 10秒待機 task.wait(10) -- 3. ゴーストモデルをReplicatedStorageから複製してワークスペースに配置 local ghost = ghostModel:Clone() ghost.Parent = workspace -- 4. ghostDataのインデックスを1から順に再生 for i, frame in ipairs(ghostData) do ghost.PrimaryPart.CFrame = frame.cframe task.wait(1/60) -- 60FPS相当で再生 end -- 5. リスタート後はゴーストと競走

確認ポイント
ゴースト再生中に自分も走れること、ゴーストに当たっても弾かれないことを確認する。

👥 発展 4人マルチプレイへの拡張
変更点1人プレイ → 4人プレイに変えるポイント
項目1人プレイ4人プレイ
カート数1台4台（コースのスタート位置に等間隔で配置）
ゴーストシステムあり削除（ゴーストなしの別ルーム）
カウントダウン開始条件ゲーム開始時4人目がシートに座った瞬間
カメラ1つ（自分のカート追従）各プレイヤーが自分のカートを追う（変更不要）

実装のポイント

  • VehicleSeatのOccupant（乗っている人）を監視して4人全員がそろったら raceStarted = true にする
  • 各プレイヤーのカメラはLocalScriptで自分のカートを追うようにしているので変更不要
  • アイテムボックス（バナナ・甲羅・キノコ）はそのまま流用できる
⭐重要ポイント
  • ⭐ スタートライン・ゴールラインは CanTouch = ON のまま残すこと — これがないとTouchedイベントが発火しない
  • ⭐ コース復帰スクリプトは ServerScriptService に置く — LocalScriptでは他プレイヤーに位置変更が反映されない
  • ⭐ 「コースアウト2秒・1秒前に戻る」の2つの数値は別々に設定されている — 混同しないこと
  • ⭐ ゴーストモデルは必ず ReplicatedStorage に置く — Workspace に直接置くとゲーム開始前から見えてしまう
  • ⭐ 4人マルチプレイへの変更は「ゴーストを消す + カート4台 + 最後の1人が座ったらスタート」の3点だけでOK
🚧初心者がつまずきやすい点
❌ ゴールラインを通っても反応しない
↓
✅ CanTouch が OFF になっている — ON にするとTouchedイベントが動き始める
❌ コースアウトしても復帰しない
↓
✅ コースのパーツ名がスクリプトの参照と一致していない — workspace内のパーツ名を確認して変数の文字列と完全一致させる
❌ ゴーストが出現しない・エラーが出る
↓
✅ ReplicatedStorage に「ゴーストモデル」という名前でモデルを入れていない — 名前を完全一致させる
❌ ゴーストに当たってカートが弾き飛ばされる
↓
✅ ゴーストモデルの全パーツの CanCollide が ON のまま — 全パーツを選択して OFF に変更する
❌ カウントダウン中にカートが動いてしまう
↓
✅ スタートフラグ（raceStarted）のチェックが抜けている — Throttle入力を受け取る前にフラグを確認する処理を追加する
